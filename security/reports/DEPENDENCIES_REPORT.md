# DEPENDENCIES Security Report

## Status: PASS (fixed 2026-10-15; CI audit job not yet run)

## Findings

- Originally `requirements.txt` pinned 8 direct dependencies exactly, but transitive ones (`urllib3`, `Werkzeug`, `Jinja2`, `numpy` and others) floated. Two deploys could install different code, and the SSRF fix depends on urllib3 internals.
- Fixed: the direct pins moved to `requirements.in` and `requirements-selenium.in`. `requirements.txt` (41 pins) and `requirements-selenium.txt` (52 pins) are now hashed lock files generated by `uv pip compile --universal --python-version 3.11 --generate-hashes`. They resolve for every platform and for Python 3.11 and later, with environment markers where versions differ (for example `numpy` 2.4.6 on 3.11, 2.5.4 on 3.12+). Shared pins are identical across the two files.
- Because every line carries a hash, pip switches to hash-checking mode automatically: Railway, CI and `pip install -r requirements.txt` all install exactly the audited files.
- The lock was installed with `--require-hashes` into a fresh Python 3.14 venv on macOS and the test suite run against it.
- All 52 pinned versions across both locks were checked against the OSV database on 2026-10-15: no known vulnerabilities.
- `pip-audit` was not run locally. It is defined in the CI `dependency-audit` job.

## What's at risk

Little remaining. Python itself is not pinned for Railway (no `.python-version` or `runtime.txt`), so the deploy uses whatever Python Nixpacks defaults to. The lock covers 3.11 and later either way.

## What's already secure

Hashed, fully pinned locks for runtime and Selenium sets; GitHub Actions pinned to commit SHAs; a CI audit job.

## Recommendations

1. Let the CI `dependency-audit` job run on the next push, or run `pip-audit -r requirements.txt -r requirements-selenium.txt` locally.
2. Optionally add `.python-version` containing `3.12` so Railway and CI use the same interpreter.
3. `.github/requirements-ci.txt` (ruff, pip-audit) pins direct versions only; lock it the same way if CI reproducibility matters.
